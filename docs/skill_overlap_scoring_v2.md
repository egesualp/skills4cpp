# Documentation: `skill_overlap_scoring_v2.py`

## Overview
The `skill_overlap_scoring_v2.py` script computes skill-based scores for **Career Path Prediction (CPP)**. It evaluates how well a candidate's past skills overlap with the skills required by a potential next occupation. This score is used to rank candidate occupations, based on the intuition that users are more likely to transition to jobs that utilize their existing skill set.

The script supports two primary modes of operation depending on the dataset type:
1.  **Job ID Mode** (for `decorte`): Uses predicted skills linked to specific job IDs.
2.  **ESCO Mode** (for `decorte_esco`): Uses direct ESCO title lookups to infer skills.

## Mathematical Formulation

The core metric computed is the **Skill Overlap Score**, defined as the proportion of the target occupation's required skills that are present in the user's career history.

$$
S_{\text{SKILLS}}((occ_1, \dots, occ_N), occ_{\text{target}}) = \frac{|S_{\text{career}} \cap S(occ_{\text{target}})|}{|S(occ_{\text{target}})|}
$$

Where:
*   **$S_{\text{career}}$**: The union of all skills associated with the user's past occupations ($occ_1, \dots, occ_N$).
    $$ S_{\text{career}} = \bigcup_{i=1}^{N} S(occ_i) $$
*   **$S(occ_{\text{target}})$**: The set of skills required by the candidate target occupation, derived from the ESCO ontology.
*   **$| \cdot |$**: The cardinality (number of elements) of the set.

> **Note:** If the target occupation has no mapped skills ($|S(occ_{\text{target}})| = 0$), the score is defined as $0.0$.

## Execution Flow

### 1. Initialization & Configuration
The script starts by parsing command-line arguments to determine the operating mode and data paths.
- **Mode Detection**:
    - If `--skill_scores_file` is provided $\rightarrow$ **Job ID Mode**.
    - If `--skill_scores_file` is NOT provided $\rightarrow$ **ESCO Mode**.

### 2. Data Loading
The script loads necessary data resources:
*   **Career Skill Map** (Job ID Mode only): Loads a JSON file (e.g., `best_fused_scores.json`) mapping `job_id` $\rightarrow$ `skills`.
    - *Optional Filtering*: Can restrict to top-k skills per job using `--top_k_skills`.
*   **ESCO Ontology**:
    - **Occupations**: Maps occupation titles to ESCO URIs.
    - **Relations**: Maps ESCO occupation URIs to sets of Skill URIs.
*   **Dataset**: Loads the standard CPP dataset splits (Train/Val/Test) using `cpp.data_classes.Data`.

### 3. Preprocessing & Formatting
*   **Target Skills Precomputation**: Iterates over all unique target labels in the dataset and caches their required skills ($S(occ)$) for efficient lookup during scoring.
*   **History Processing**:
    - If `--last_job_only` is active, the history is truncated to consider only the most recent occupation ($occ_N$).

### 4. Scoring Loop
For each sample in the dataset (History $H$, Target $T$):
1.  **Determine Career Skills ($S_{\text{career}}$)**:
    - **Job ID Mode**: Retrieves job IDs associated with $H$ and unions their skills from the loaded Career Skill Map.
    - **ESCO Mode**: Splits $H$ into titles, maps them to ESCO URIs, and unions their skills directly from the ESCO ontology.
2.  **Score Candidates**:
    - Iterates through **all possible target occupations** in the dataset.
    - Computes the update overlap score: $\frac{|S_{\text{career}} \cap S(candidate)|}{|S(candidate)|}$.
3.  **Track True Target**: Identifies the index of the actual ground-truth target for evaluation.

### 5. Evaluation & Output
*   **Metrics**: Calculates ranking metrics like **MRR** (Mean Reciprocal Rank) and **Recall@K** (R@1, R@5, R@10, R@20) based on the computed scores.
*   **Logging**: Reports metrics for each split (Train, Val, Test).
*   **Saving**:
    - Saves computed scores to `.pkl` files if `--save_scores` is enabled.
    - Saves metrics summary to `metrics.json`.

## Preprocessing Steps Detailed

### A. Skill Mapping (ESCO-based)
*   **Normalization**: Occupation titles are normalized (lowercase, strip whitespace) before matching.
*   **Prefix Handling**: Prefixes like "esco role:" or "role:" are stripped if exact matching fails.
*   **Relation Lookup**: Uses the `occupationSkillRelations_en.csv` to find all skills (essential & optional) linked to an occupation URI.

### B. Job ID Skill Extraction (Job ID Mode)
*   **Source**: Skills are sourced from a JSON file generated by a prior step (usually an embedding-based retrieval process).
*   **Filtering**: If `top_k_skills` is set, the script sorts skills by their confidence score and keeps only the top $K$.

## Key Arguments

| Argument | Description | Default |
| :--- | :--- | :--- |
| `--data_type` | Dataset identifier (e.g., `decorte`, `decorte_esco`). | `decorte` |
| `--skill_scores_file` | Path to JSON mapping `job_id` to skills. Triggers **Job ID Mode**. | `None` |
| `--occupations_file` | Path to ESCO occupations CSV. | `data/esco_datasets/occupations_en.csv` |
| `--relations_file` | Path to ESCO occupation-skill relations CSV. | `data/esco_datasets/occupationSkillRelations_en.csv` |
| `--top_k_skills` | Filter to top K skills per job (Job ID Mode only). | `None` (All) |
| `--last_job_only` | Restrict history to only the user's last job. | `False` |
| `--eval_clean_test` | Evaluate additionally on a "clean" test set (no subspans). | `False` |
| `--save_scores` | Save the resulting score matrices to disk. | `False` |
